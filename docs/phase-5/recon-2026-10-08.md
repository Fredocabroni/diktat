## B. Raw SEC press-release titles — 100% of recent Drops

**Finding.** Every one of the last 7 Drops (2026-10-02 → 2026-10-08) rendered the raw primary-source press-release title verbatim as the Drop headline. The AI rewrite returned empty-string for the entire window; the handler fell back to `source_title`.

**Where it comes from.**

- Fallback branch: [`apps/workers/src/jobs/drop-publish.ts:323-324`](../../apps/workers/src/jobs/drop-publish.ts#L323) — `const finalHeadline = rewrite.headline.length > 0 ? rewrite.headline : sel.chosen.source_title;` identically for `finalSummary`.
- The rewrite caller [`drop-publish.ts:475-513`](../../apps/workers/src/jobs/drop-publish.ts#L475) (`rewriteHeadlineSafely`) returns `{ headline: '', summary: '', claim: '' }` on three failure modes: `deps.invoke` not configured (logs `drop_publish.rewrite_skipped reason: no_invoke`), model error / Zod parse failure (logs `drop_publish.rewrite_failed` with scrubbed message), or model returning empty strings (no log — treated as success).
- The prompt that drives the model: [`packages/ai-fabric/src/prompts/drop-headline.ts:29-57`](../../packages/ai-fabric/src/prompts/drop-headline.ts#L29). **The last line is "Empty output is preferred to a slanted rewrite."** Combined with rule 1 (strip source-side editorialization — the SEC's "Historic Reform" wording), rule 5 (no hedge words — bans "may/could/potentially" which press releases use heavily), and rule 8 (hard 100-char cap, soft 40-80 — most SEC titles exceed), the model's path of least resistance on an SEC press release is the empty-output escape hatch.

**Why is the fallback firing — "empty output" vs. error?**

- **No evidence of error-mode failures in the handler.** The three error logs (`drop_publish.rewrite_skipped reason: no_invoke`, `drop_publish.rewrite_failed`, and `drop_publish.rewrite_cost_exceeded`) all alert in Railway if they fire; prior session reported no such entries over the 7-day window.
- **I did NOT re-pull Railway logs in this session** (no Railway access from this environment). The prior session's log review stands; a 30-second check on Railway for `event: drop_publish.rewrite_failed` since 2026-10-02 is the one open verification.
- Conclusion with current evidence: the model is returning empty JSON by design — the prompt tells it to. Over seven days of SEC-dominated candidates, that's "always."

**Supporting prod evidence (prior session, re-stated for the record).**

- Last 7 days of Drops (`select drop_at, source_title, headline from public.news_topics where is_drop and drop_at >= now() - interval '7 days'`): all 7 rows have `headline = source_title` character-for-character.
- `news_topics` has **no persisted `headline_rewritten` boolean** — only the log stream indicates rewrite outcome. The 100% match is proof-by-string-comparison.
- Source-provider breakdown (prior session, `select source_provider, count(*) from public.news_topics_candidates where created_at > now() - interval '7 days' group by source_provider`): SEC EDGAR is the only non-zero fresh-insert source. BLS and Congress adapters are healthy-polling but have never produced a fresh insert — the primary-source feeds are low-cadence relative to SEC's torrent.

Verification query I would run with DB access (operator can paste into Supabase):

```sql

       case when headline = source_title then 'fallback' else 'rewritten' end as outcome
  from public.news_topics
```

## C. Take 5 counting loophole — every row, not distinct topics

**Finding.** The trigger counts every `opinion_shifts` INSERT. Flipping stance 5 times on one card (each flip with a fresh `client_key`) marks Take 5 complete. The streak system is trivially gameable today.

**Trigger body.** [`supabase/migrations/20260525120000_streak_engine.sql:294-315`](../../supabase/migrations/20260525120000_streak_engine.sql#L294):

```sql
create or replace function public.opinion_shifts_credit_take5()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
begin
  begin
    perform public.increment_take5_progress(new.user_id);
  exception when others then
    raise warning 'opinion_shifts_credit_take5 failed for user_id=%: %',
      new.user_id, sqlerrm;
  end;
  return new;
end;
$$;

create trigger opinion_shifts_take5_after_insert
  after insert on public.opinion_shifts
  for each row execute function public.opinion_shifts_credit_take5();
```

**Writer body.** [`supabase/migrations/20260525120000_streak_engine.sql:93-102`](../../supabase/migrations/20260525120000_streak_engine.sql#L93):

```sql
update public.streaks
set take5_progress = case
      when take5_local_date is null or take5_local_date < v_today then 1
      else take5_progress + 1
    end,
    take5_local_date = v_today,
    updated_at = now()
where user_id = p_user_id
returning take5_progress into v_progress;
```

**No DISTINCT-topic check anywhere.** Writer increments by 1 or resets to 1 at day change. The RPC's idempotency fast-path ([`record_opinion_shift` ON CONFLICT NO-OP](../../supabase/migrations/20261010000000_record_opinion_shift_rpc.sql)) prevents a same-`client_key` retry from double-counting, but any flip with a new `client_key` is a fresh row → fresh trigger → +1. The operator's phone test (6 taps = Take 5 complete) is reproducible by design.

**Verification query** (operator to run on prod):

```sql
-- Today's shifts grouped by topic for the most recently touched streak.
with latest as (
  select user_id from public.streaks
   where take5_local_date = (now() at time zone timezone)::date
   order by updated_at desc limit 1
)
select os.topic_id,
       nt.headline,
       count(*) as shifts_today,
       min(os.created_at) as first_shift,
       max(os.created_at) as last_shift
  from public.opinion_shifts os
  join latest on latest.user_id = os.user_id
  left join public.news_topics nt on nt.id = os.topic_id
 where os.created_at::date = current_date
 group by os.topic_id, nt.headline
 order by count(*) desc;
```

If `shifts_today > 1` on any `(user_id, topic_id)` row, that is a user with the loophole live. The user's own account from the phone test is the obvious case to inspect.

### D.4 Rewrite prompt — real-people silence

[`packages/ai-fabric/src/prompts/drop-headline.ts:29-57`](../../packages/ai-fabric/src/prompts/drop-headline.ts#L29). Ten hard constraints. **Rules 2 and 6 require preserving every name verbatim. Rule 7 keeps person names at canonical capitalization.** No rule addresses:

- Presumption of innocence on named people in enforcement actions.
- Charged vs. convicted — "SEC charges X" vs. "X committed fraud." The source title is often a charge; the Drop card asks Agree / Disagree on the headline as a proposition.
- Private facts, personal relationships, health, immigration status, religion, sexuality.
- Children, uncharged third parties, witnesses.

Today's 2026-10-07 Drop ("SEC Seeks Final Judgment Against Former Western Asset Co-CIO Ken Leech in Cherry Picking Case" — prior session) is a procedural posture that the Drop card framed as an agree/disagree proposition. The semantic mismatch (procedural fact vs. opinion claim) is the surface UX bug; the real-people silence in the prompt is the deeper integrity issue.

**Output schema** that governs the model's return shape — [`drop-publish.ts:92-116`](../../apps/workers/src/jobs/drop-publish.ts#L92):

```ts
const DropHeadlineRewriteSchema = z.object({
  headline: z.string().max(100), // empty allowed
  summary: z.string().max(240), // empty allowed
  claim: z.string().max(240), // empty allowed
});
```

Every field permits empty — the "empty output preferred" escape hatch has schema-level backing.

## PROPOSALS (reviewer — not yet accepted)

Each item: what/why, smallest safe PR, risks, migration y/n. Ranked at the bottom by "unblocks the 50-user soft launch."

### P1 — No raw-title fallback

**What.** When `rewrite.headline` is empty OR `rewrite.claim` is empty, skip this candidate entirely and move to the next in the pool. If every candidate returns empty, publish NO Drop that day.

**Why.** Today the fallback produces 100% raw press-release titles that aren't opinion-shaped. Pairs with DIRECTION 2 (scarcity OK).

**Smallest PR.** One-line change in `drop-publish.ts:323-324` plus a short loop in `selectDropFromPool` to pick the next candidate on an empty-rewrite result. Tests: expand the existing drop-publish test fixtures to assert "empty rewrite skips candidate" and "all-empty pool publishes nothing."

**Risks.** Currently the rewrite returns empty on every SEC item. Without P4 (Take 5 pool from archive + evergreen) OR a trending-signal pipeline (D.1), P1 may ship as "no Drop ever." **Must land after P4 or a non-SEC source lands fresh rows.**

**Migration.** No.

### P2 — Visible tap feedback + Take 5 progress on Home

**P2.a (card):** `StanceButton` gains a `pressed`/`selected` prop; the tapped button becomes sticky-on (filled with checkmark), the other two dim, a confirmation pill reads "Recorded · agree." On change-of-mind, selected moves and a 30s undo pill shows.

**P2.b (home):** `●●●○○` dot row at the top of the Drop card showing `take5_progress / 5` from `streaks.take5_progress`. One pulse per tap; on completion ●●●●● with a single-fire "Take 5 complete" affirmation.

**Why.** The current UI gives zero positive feedback on success. The error branch has a live region ([`DropFeedClient.tsx:188`](../../apps/web/components/drop/DropFeedClient.tsx#L188)); the success branch has nothing.

**Smallest PR.** Web-only. Modify `DropCard.tsx` (StanceButton + optional selected pill), `DropFeedClient.tsx` (local selected state + user.me invalidate on success), add dot row component. No API change, no migration. **Must ship AFTER P3** or the dot row will show the gameable count.

**Risks.** `addiction-auditor` reviews the completion affirmation (don't let a copy-linter miss make it chirpy). No infinite-loop risk; the dot row is bounded 0..5.

**Migration.** No.

### P3 — Take 5 counts distinct topics, not taps

**What.** Enforce one credit per `(user_id, topic_id)` per local day.

**P3.a (DB-side, cleanest):** rewrite `increment_take5_progress` to accept `p_topic_id uuid`, and `return` early with `jsonb_build_object('progress', v_progress, 'noop_reason', 'already_counted')` if a prior shift exists on this topic for this user today-local. Change the trigger to pass `new.topic_id`. The existing `(user_id, topic_id, created_at)` composite index already supports the check.

**P3.b (less invasive):** keep the trigger as-is but add a `distinct_topics_today` counter alongside `take5_progress` and expose that to the UI.

**Why.** Closes the one-card-flip-5× loophole from C.

**Smallest PR.** Single migration adding the new `increment_take5_progress` overload + trigger swap + unit test asserting "same topic twice = +1 total." Rollback is a one-line revert of the trigger. **Must apply BEFORE P2.b surfaces the counter to users.**

**Risks.** The existing single-arg signature stays live for `apply_local_boundary_sweep` / `evaluate_risk_push` callers (none call it directly today — only the trigger does). Grep check before merge.

**Migration.** Yes. New timestamp > `20261010100000` (the pending #182 migration) → use `20261011000000_take5_distinct_topics.sql` or later.

### P4 — Take 5 pool = last-N-days archive + evergreen bank

**What.** A `/take5` route that renders a stack of 5 cards: today's Drop (if any) + N days of past Drops the user hasn't yet stanced + evergreen questions when the archive is thin.

**Why.** Even with P3 enforcing distinct topics, a one-Drop-per-day cadence makes "5 distinct topics today" literally unreachable. The archive makes it possible without pulling tomorrow's content forward.

**Smallest PR.** This is the biggest proposal — would prefer a 2-PR split:

- **4.a (archive-only):** new `/take5` route; new tRPC `feed.take5Pool` returning up-to-5 topics (today's Drop + un-stanced past Drops from last 7 days). No new table.
- **4.b (evergreen bank):** new `evergreen_stance_bank` table (operator-authored, not AI-generated — the integrity contract bars AI-authored stance prompts); seed; include in pool when archive is thin.

**Risks.** `/take5` creates a second surface where `opinion_shifts` fire. Every path must flow through `record_opinion_shift` (which is the only writer post-#182 anyway). `addiction-auditor` reviews cadence — hard cap at 5 cards per local day, no infinite scroll.

**Migration.** 4.a: no. 4.b: yes (`evergreen_stance_bank` + seed).

### P5 — Rewrite prompt real-people clause

**What.** Add a hard constraint to `DROP_HEADLINE_REWRITE_SYSTEM_PROMPT`:

```
X. REAL PEOPLE CLAUSE. Claims that name a real person must be about the
   policy, the agency action, or the public-record procedural fact — never
   assert the named person's guilt, intent, or private facts. Distinguish
   "SEC filed suit against X alleging fraud" (procedural fact) from "X
   committed fraud" (an assertion the primary source has not established).
   Required framings for pending actions: "alleged" / "charged" / "accused"
   / "sued". Convictions, entered judgments, or admitted conduct may be
   stated as fact once the primary source documents the finding.

   Never include:
     - minor children's names
     - home addresses, phone numbers, personal email
     - health, sexuality, religion, immigration status
     - family members not themselves party to the public action

   If the source title asserts guilt on a pending matter, rewrite to the
   procedural posture or return an empty headline.
```

**Why.** The prompt currently preserves names verbatim with no clause distinguishing a charge from a conviction. The Drop card then asks "Agree / Disagree" on the headline.

**Smallest PR.** Single-file edit to [`drop-headline.ts`](../../packages/ai-fabric/src/prompts/drop-headline.ts). `copy-linter` + manual neutrality review on PR. The pending `neutrality-auditor` subagent (named in Phase 4 pre-launch queue) is the long-term gate; manual review stands until it ships.

**Risks.** Prompt change may increase the empty-output rate further — pairs with P1's "no fallback" by making empty more common. Mitigate by shipping P5 first and watching the rewrite-success rate before shipping P1.

**Migration.** No.

### P6 — Show vote split after the user votes

**What.** On successful `recordShift`, reveal:

- Aggregate: "47% of 1,284 agreed. 32% skipped. 21% disagreed." (`select stance, count(*) from opinion_shifts where topic_id = $1 group by stance`.)
- User's own trajectory on this topic if change-of-mind rows exist: "7 days ago: Disagree → Today: Agree."
- One soft nudge: "Come back tomorrow — same question, see how the room moved."

**Why.** No feedback → no return. The "see how the room moved overnight" line is the return-driver on no-Drop days.

**Smallest PR.** New tRPC procedure `feed.topicAggregate(topicId)` returning stance counts; server-side only; no new table (reads existing `opinion_shifts`); `queryLimit` ~60/min; caches well. Web consumer in `DropFeedClient` on the mutation's `onSuccess`.

**Risks.** Aggregate privacy on tiny N — with 67 users today, a day-old Drop may be `1/1 agreed`. Threshold: hide numeric aggregate when `count < 5`; show the trajectory + nudge only. `addiction-auditor` reviews the nudge copy (no fake-urgency framing).

**Migration.** No.

### P7 — Addiction-auditor gates every retention mechanic in this phase

**What.** Every PR in P2 / P4 / P6 passes `addiction-auditor` as a merge gate. Non-starters (reaffirmed, not new):

- No fake urgency ("Only 2 hours left!" when nothing expires).
- No guilt copy ("You haven't shown up in 3 days").
- No streak-shaming on break (silent per §11.5 — already enforced in the engine).
- No "you'll lose X" framing on push.
- No infinite-scroll trap on `/take5` (hard 5-card cap).
- No variable-reward schedule tied to real money (AP-only).

**Smallest PR.** No new code — this is a workflow gate. One-line addition to CODEOWNERS or the PR template so the subagent fires automatically on P2 / P4 / P6 PRs.

**Risks.** None. Low-effort hardening.

**Migration.** No.
